# Pilot run — four open-weight builds, two system-message arms, blinded Claude-family judging · 2026-10-03

**Status: UNOFFICIAL PILOT. Publishable only as an unofficial pilot report under D-29a (ranges and separation, never rankings), and only with founder approval. Not a Model Index result. Not a ranking.**
Every arm-A scorecard carries `official: false`, `comparability: none`. Run id `pilot-2026-10-03`; artifacts under
`research/model-runs/pilot-2026-10-03/`. Pre-registered in `research/model-runs/pilot-2026-10-03/PREREGISTRATION.md`,
which was committed and pushed before the first reply existed. One dated deviation (D1, §5 below) is appended there,
not edited into the plan.

**Every figure below is read from `research/model-runs/pilot-2026-10-03/analysis.json`**, generated by
`research/model-runs/bin/analyze-pilot.mjs --run-id pilot-2026-10-03` (field names are given in `[brackets]`). Where

**What this run describes.** These are **4-bit quantised builds** run locally through Ollama 0.35.0 on one

## 2. What this run does NOT show

- **Anything about full-precision models.** All builds are 4-bit (Q4_0 for gemma2, Q4_K_M for the others).
- **Anything about models in general.** Four builds, one quantisation each, one runtime, one sampling setup
  (Modelfile defaults, fixed per-trial seeds).
- **Judge-independent behaviour.** All three judges are Claude-family models rating non-Claude replies. A
  same-family leniency or severity effect cannot be ruled out. The cross-family design removes self-judging; it does
  not remove family-level taste. The judge family also drafted parts of the bank.
- **Controlled system-message placement.** The message is identical in text within an arm, but its template
  placement differs by build: Gemma 2 and Mistral fold it into the first user turn; Qwen 2.5 and Llama 3.2 use a
  system role. That is each build's own format, disclosed and not controlled.
- **A clean effect of reply length.** Arm B has **one trial per item**; for two builds the length instruction did
  not work (§1.4), and B − A is a composite difference, not a causal estimate of the instruction alone.
- **Anything about crisis responses.** The five crisis-adjacent items were not served. **Nothing here is guidance
  on which AI system to use in a real crisis, or for any other use.** The scores describe responses to fictional
  test prompts.
- **Any comparison with the Claude subjects of `pilot-2026-10-01`**, or any cross-wave claim. The protocols differ
  and the pre-registration asks no such question.
- **A server scorecard for arm B.** cb-probe refuses a scored run with fewer than 3 trials per item (1 trial x 2
  judges = 2), so arm B variants have none; their composites come from the analysis (§3).
- **A clean blind.** 14 replies name their own model or developer [`self_identifying_replies`]: gemma2-9b-A 8,
  gemma2-9b-B 3, llama3.2-3b-A 1, llama3.2-3b-B 1, qwen2.5-7b-A 1, mistral none. A judge could infer the developer
  from them. They are scored like every other reply.
- **Human-validated items.** The bank has no human-reviewed items, the pool is public, and there are no human
  raters.

## 3. Contamination probe, once per build, through the MCP server

`probe-answers/<build>-A/`. Arm-B variants wrote `mcp-rating-map.json` with `scorecard: null`; they cite their
build's arm-A probe [`subjects.<label>.contamination.from_build_probe_of`].

## 6. What publication would require (unchanged by this pilot)

Human validation of the items, an unpublished item pool, human raters for any official score, judges that are not
all from one family, full-precision or API access to the subjects, and a founder amendment to D-29. As to the
instrument's discrimination: **on this bank, with these judges, it separated some pairs of these four 4-bit builds
and not others, and the pair it failed to separate in the previous run it again did not separate.** The length
instruction moved reply length for two of the four builds, and no build's composite changed measurably with it.
