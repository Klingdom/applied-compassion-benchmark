# Learn brief 11 - QA / mechanical gates (2026-10-14)

Lens: what must be gated by a test, so Learn cannot teach something false or unsafe. A page that "looks right" is not evidence. Every gate below has a test, a planted probe that must fail it, a real fixture that must pass, and the gate it extends.

## Evidence base (what the repo already does)

- DC-02 has recurred four times (`docs/DEFECT_CLASS_REGISTRY.md` row DC-02): the /80 base model, "balanced beats spiky", the MS-5 false claim (two consistency steps unreachable, an impossible 0.5 premium, a false 70/70-vs-90/40 claim), and the task-bank item claim. Each time the class jumped to a surface the gate did not cover. Learn is a new surface and will be hit unless the gate is extended before the copy is written.
- `site/scripts/test-method-claims.mjs` recomputes from `site/scripts/lib/scoring.mjs` and imports chart data modules directly (`consistencyStepsData.ts`, `integrationPremiumExamples.ts`). It admits that page prose is re-declared as fixtures, which is the weak point (header comment, lines 18-24).
- DC-03 (`docs/DEFECT_CLASS_REGISTRY.md`): narrating an unapplied proposal as a published movement. Its 2026-10-14 note says a new route (`MovementDeltaStrip.tsx`) escaped the gate. The same will happen to Learn "real example" pages that quote score changes.
- `site/scripts/test-no-stale-counts.mjs` scans only `src/app/**/*.tsx` and `src/components/**/*.tsx`. It does NOT scan `src/data/**`. If Learn copy lives in a data file (likely, for reading-level variants), it escapes the gate.
- `site/scripts/lib/html-gate-harness.mjs` plus `test-model-html-leak.mjs` establish the house pattern: planted probes first, then the real built tree in `site/out`, fail on zero matches. Reuse it; do not invent a new harness.
- Scoring facts the experiment must honour (`site/scripts/lib/scoring.mjs`): dimensions are 0-5; `dimScores[c] ?? 1` silently defaults a missing dimension to 1; any dimension equal to 0 forces premium 0; the consistency multiplier steps at sigma 1.5 / 3.0 / 5.0 but sigma can never exceed 2.5, so only two steps are reachable; weakness factor counts dimensions below 4.0; composite is rounded to 0.1 and bands use inclusive upper edges (20 is Critical, 20.1 is Developing; 40/40.1, 60/60.1, 80/80.1).

## Gates

### QA-R1 - Learn method claims are gated, with no re-declared fixtures
- Test: extend `test:method-claims` (`site/scripts/test-method-claims.mjs`) so every numeric method fact Learn publishes is exported from a plain `.ts` data module (e.g. `site/src/data/learn/methodFacts.ts`: sigma steps, reachable premium set, band edges, dimension count, 0-5 range, base formula text constants). Prose components render from that module; the test imports it and recomputes against `scoring.mjs`. Add a lint over Learn `.tsx`/data prose for numeric method sentences ("sigma", "premium", "band", "out of 100", "weighted") that are NOT sourced from a facts import, failing on any literal not found in the facts module.
- Planted probe: facts module contains `premium: 0.5`, or a step `sigma 3.0-5.0 -> 0.4` marked reachable, or Learn copy says "a balanced profile always beats a spiky one". Each must fail by naming the value.
- Real fixture that must pass: the reachable set `{0, 1.5, 2, 3, 4, 4.5, 6, 8, 10}` and MAX sigma 2.5; the 3.8x8 = 70.0 vs [5,5,5,5,2.6,2.6,2.6,2.6] = 72.0 pair, taught as "not always".
- Extends: `test:method-claims`; reuses the ban list already implied by DC-02 (the "base /80" and "balanced beats spiky" phrasings become denied strings across `src/app/learn/**`).

### QA-R2 - Experiment fidelity, including band boundaries
- Test: new `test:learn-experiments`. The build-a-score component must call `computeCompositeFromDimensions` from `site/src/lib/scoring.ts` (never a copy); gate that source has no second implementation (grep for `/ 4) * 100`, `0.75`, `weaknessFactor` outside `scoring.*`). Then run a fixture table through BOTH the component's pure compute function and `scoring.mjs` and require identical `{composite, band, integrationPremium}`. Also assert `scoring.ts` and `scoring.mjs` agree on the table (they claim to mirror each other, which `test:scoring` covers; assert it again from the Learn side).
- Fixture table (must include): all 0s (0.0 Critical, premium 0); all 1s (0.0); all 5s (100, Exemplary); one dimension 0 and seven 5s (premium forced 0, so base only); 4.0 x 8 versus 3.99 x 8 (weakness cliff at 4.0); sigma exactly 1.5 (e.g. a profile engineered to hit 1.5 within float tolerance) and just above; profiles landing at 20.0 / 20.1, 40.0 / 40.1, 60.0 / 60.1, 80.0 / 80.1 after rounding (search the grid at 0.1 steps for exact hits and pin them); a raw value of 20.04 (rounds to 20.0, Critical) versus 20.05 (20.1, Developing), which tests the rounding-then-band order; a clamp at 100 (base 95 plus premium 10).
- Planted probe: mutate the component to band before rounding, to use `<` instead of `<=` at an edge, to default a missing slider to 0, or to forget the zero-dimension rule. Each must fail a named fixture. Slider granularity: if sliders step 0.5 or 1, the fixture table still runs the whole 0.1-grid so the experiment is correct for any granularity.
- Real fixture: the published Abridge worked example already pinned by `test:method-claims` (check 5), plus the "reproduce a published composite" Analyst task: take 3 real entities from `site/src/data/indexes/*.json` with dimension scores and require the experiment to reproduce the published composite within 0.1. If any published composite fails to reproduce, that is a data defect to report, not a test to loosen.
- Extends: `test:scoring`, `test:method-claims`.
- Also gate dice/bootstrap demos: seed the PRNG in test mode and assert the displayed interval contains the true mean at the stated coverage over N=1000 seeded runs (tolerance stated), and that the copy never says "proves" or "exact".

### QA-R3 - No hard-coded counts, including Learn data files
- Test: extend `test:no-stale-counts` (`site/scripts/test-no-stale-counts.mjs`) SCAN_ROOTS to add `src/data/learn/**` (prose JSON/TS) and any markdown shipped as educator packs. Add Learn-specific nouns: "40 subdimensions", "8 dimensions", "5 bands", "eight dimensions", "forty" must come from `dimensions.ts` / `scoring` exports (`DIMENSION_CODES.length`, `BAND_ORDER.length`). Also scan the built `site/out/learn/**` for catalogue numbers equal to any current count (1,325, 447, 191, ...) that did not come from a template (compare against `build-manifest.json`: a number is allowed only if it equals the current value, which proves it is derived, and the source scan proves it is not typed).
- Planted probe: `<p>We score 1,156 institutions</p>`, `{"text": "seven indexes"}` in a Learn data file, and a printable page with `1,325 entities` typed literally.
- Real fixture: a Learn page rendering `SCORED_ENTITY_COUNT_FORMATTED` from `site/src/data/entityCount.ts`.
- Caveat to state to the coordinator: "8 dimensions / 40 subdimensions" is structural (`dimensions.ts`), not a catalogue count; it is allowed only if rendered from the module, so the ban stays mechanical. Printable PDFs/handouts freeze a number at print time: they must carry "as of <date>" generated from the manifest, and a stale-handout check compares the date to the manifest.
- Extends: `test:no-stale-counts`.

### QA-R4 - Privacy gate on built Learn HTML and JS
- Test: new `test:learn-privacy`, built on `html-gate-harness.mjs`, run over `site/out/learn/**` and the JS chunks that only Learn routes reference (map route to chunks via the Next build manifest; if mapping is unreliable, scan ALL chunks and allowlist the known layout-level Umami loader). Fail on: any `<form`, `<input type=text|email|search|password`, `<textarea`, `contenteditable`, `<select>` that submits, `action=`; `fetch(`, `XMLHttpRequest`, `navigator.sendBeacon`, `WebSocket`, `EventSource`, `localStorage`/`sessionStorage`/`indexedDB`/`document.cookie` writes (a child's slider values must not persist), `<iframe`, `<script src=` or `<link href=` or `<img src=` / `srcset` / CSS `url(` to any origin other than `compassionbenchmark.com`; `mailto:` with a prefilled body; `window.open` to non-allowlisted hosts. Numeric range sliders and buttons are allowed; text-entry is not.
- Learn is built from user-free math, so this is cheap to keep at zero.
- Planted probes: each banned construct injected into a copy of a good page (one probe per construct, the harness pattern). Include a base64/obfuscated `"fe"+"tch"` probe only if the product wants to claim obfuscation resistance; otherwise state the limit: this is a lint, not a sandbox. Back it with a runtime check in the browser smoke test (QA-R9): load each Learn page with request interception and assert zero requests beyond same-origin static assets (and Umami, per the position below).
- Real fixture: a built Learn page containing only same-origin assets and range inputs.
- Umami position: the layout loader (`site/src/app/layout.tsx`, comment around line 149) is global. My recommendation is to keep page-view-only Umami (self-hosted, no cookies) but fire NO custom events from Learn, so nothing a child does is tracked. Gate: Learn sources must not import `site/src/lib/analytics.ts` or call `umami.track`. Planted probe: an `onClick` calling `track(...)` inside Learn. If the founder prefers zero analytics on Learn, the cheaper-and-stronger option is to suppress the loader on `/learn/*` and gate its absence in built HTML.
- Extends: `test:model-html-leak` pattern, `test:product-separation` (the Agent Hub boundary: see QA-R6).

### QA-R5 - Duty of care on Explorer pages (and entity names on Explorers/Investigators)
- Hard rule to gate: Explorer pages contain NO real scored entity and no distressing vocabulary. Investigators get real entities only from an allowlisted set, never a bottom-ranked-framed list.
- Test: new `test:learn-duty-of-care`, two scans on Explorer routes' built text (strip tags, scripts, SVG geometry):
  1. Entity-name scan: build a name set from every `site/src/data/indexes/*.json` entity name plus slugs (use the same loader as `test:entity-href`), including aliases and `test:encoded-names` variants, matched word-bounded and case-insensitive. Any hit on an Explorer page fails, except a short allowlist of fictional-collision names that you maintain explicitly (a fictional town named "Springfield" must not collide with a real city; the test will tell you).
  2. Vocabulary scan: a deny list kept in one file (`site/src/data/learn/duty-of-care-vocab.ts`), seeded from `site/src/components/model-benchmark/dutyOfCare.ts` and extended: war, genocide, execution, torture, massacre, rape, abuse, suicide, self-harm, killed, death toll, detention, famine, starvation, trafficking, bomb, shooting, and similar, with stem handling (kill*, murder*). Tuned per band: Explorers strict (no hit anywhere); Investigators allow a short list of terms ONLY inside a block marked `data-care-framed` that also contains a content note and a support-resource line.
  Honest limit: a vocabulary list catches vocabulary, not tone or implication ("the town where nobody comes back"). It is a floor. State in the PRD that every Explorer page needs a named human reviewer sign-off recorded in a committed file (`docs/learn/review-log.json`), and add a gate that every Explorer route has a review entry newer than the page's content hash. That makes human review mechanical to require even though it is not mechanical to perform.
- Investigators framing: real-entity pages must not render a ranking-order list sorted ascending or any "worst" token; scan for "worst", "bottom", "lowest-ranked", "this country is", "evil", "failing nation" (extend the D-29/D-29a banned-token approach to entities). Entity pages must show an uncertainty/seed caveat adjacent to any score, reusing the `seed vs measurement` markers the site already has.
- Planted probes: an Explorer page that says "the town was hit by a war" (vocab), one that names "Norway" (entity scan), one with "Sudan" in an SVG `<title>` or `alt` text (the scan must include attributes), one Investigators page showing "Lowest-ranked: <entity>".
- Real fixture: a fictional-town Explorer page and the "school library" example pass; an Investigators page with a framed entity block and content note passes.
- Extends: `test:encoded-names`, `test:entity-href` (name loading), `test:model-html-leak` (attribute coverage).

### QA-R6 - Separation, independence, no AI-model rankings, no Agent Hub links
- Test: `test:learn-separation`. In built Learn HTML: no `href` to `/agent-hub`, `/agent-self`, comments, or any UGC route from Explorer/Investigator pages (a deny pattern list from the route table); no copy implying learning improves a score ("raise your score", "boost your rating", "get a better score by"); no AI model leaderboard tokens beside a model name (reuse the `test:model-html-leak` / `test:model-benchmark-public` token rules). Extend `test:product-separation` rather than duplicating it, so the existing waiver mechanism (`test:separation-waivers`) governs exceptions.
- Planted probes: an Explorer page linking `/agent-hub`; "learn this trick to raise your institution's score"; "Model X scores 63".
- Real fixture: a Researchers page linking `/methodology` and `/ai-models/reports/<runId>` (permitted from the top band only).
- Extends: `test:product-separation`, `test:model-html-leak`.

### QA-R7 - Reading level per band
- Test: `test:learn-reading-level`, dependency-free. Implement Flesch-Kincaid grade via a ~40-line syllable heuristic in `site/scripts/lib/` and gate each page's `data-band` attribute against a ceiling: Explorers FK grade <= 5, Investigators <= 8, Analysts <= 12, Researchers uncapped. Also gate average sentence length (Explorers <= 14 words, max 22) and a ban on a jargon list per band (sigma, standard deviation, bootstrap, composite on Explorers/Investigators unless defined in a glossary tooltip on the same page). Require each page to declare its band (a missing `data-band` fails).
- Honest limit: FK is a crude proxy (it penalises long terms that are defined, and misses conceptual difficulty). Treat as a ratchet with a stored per-page grade in a committed baseline (like `test:collision-ratchet`): a page may not get harder than its recorded value, and the ceiling applies to new pages. Real child testing is the true check and is outside the gate; say so.
- Planted probe: a paragraph with 30-word sentences and "standard deviation" on an Explorer page; a page with no `data-band`.
- Real fixture: the first Explorer page, after writing, with the grade recorded in the baseline file.
- Extends: new; shape borrowed from `test:collision-ratchet`.

### QA-R8 - Accessibility, the cheapest reliable option
- Option ranking: (1) a small in-repo static lint over built HTML (cheap, no dependency, reliable for structural WCAG 2.2 failures); (2) a browser-based axe run (`@axe-core/cli` or `axe-core` with jsdom) which adds a heavy dependency and Chrome; (3) manual audit only.
- Recommendation: do (1) as a blocking gate, and (2) as a non-blocking advisory run in the founder's pre-release checklist (axe-core in jsdom cannot compute colour contrast, so it adds less than hoped; true contrast needs a real browser). For the lint, check on every Learn page: exactly one `<h1>`, no skipped heading levels, `<html lang>`, a `<main>` landmark, a skip link, every `<img>` has `alt` (and decorative ones `alt=""`), every `<svg>` that carries meaning has `role="img"` plus `<title>`/`aria-label` (hand-rolled SVG is the main risk), every `<input type=range>` has an associated label and `aria-valuetext` in words (a child using a screen reader needs "score 62, Established", not "62"), every interactive element is a real `<button>`/`<a>` (no `div onClick`), no `tabindex` > 0, link text is not "click here", target-size heuristics (WCAG 2.2 2.5.8: flag buttons with explicit width/height < 24px), no autoplay, `prefers-reduced-motion` honoured wherever animation CSS exists (grep for `animation`/`transition` and require the media-query guard), results announced through an `aria-live="polite"` region so slider output is perceivable.
- Contrast: statically compute ratio for the design tokens in `globals.css` @theme used on Learn (text on dark backgrounds, band colours). Gate each token pair actually used by Learn at >= 4.5:1 (3:1 for large text/graphics). Never rely on colour alone for bands: require the band NAME as text next to every colour swatch.
- Planted probes: an `<img>` without `alt`; a range input without a label; an `<svg>` chart without a title; a `div` with `onClick`; a band shown by colour only; a skipped `h2` to `h4`.
- Real fixture: the build-a-score page with labelled sliders and a live region.
- Extends: `test:model-report-seo` pattern for the alt-text rule (its `G20-near-model` probe already inspects `alt`).

### QA-R9 - Links resolve and printable pages render
- Test: `test:learn-links`: crawl `site/out/learn/**/*.html`; resolve every internal `href`/`src` (strip hash, trailing slash and `.html` rules per the repo convention) against the export tree and also verify `#fragment` targets exist as ids. Every simplified page must contain a link to its "full version" (`/methodology` or the relevant deep page) - assert presence AND that the target exists. Check external links are only allowlisted (research sources) and carry `rel="noopener"`; no network is used by the test. Also check the nginx redirect parity (`test:nginx-redirect-parity`) is still green when Learn routes are added.
- Printable: for each page flagged printable (`data-printable`), assert a `@media print` stylesheet exists, that print output contains no interactive-only content (a page whose only content is a slider must carry the static worked table), no dark-theme unreadability (print CSS sets light background, black text), and a "page break" marker per worksheet. Render proof: a headless-Chromium `page.pdf()` smoke test that asserts page count > 0 and extracts text (so a blank or clipped print is caught). Make the PDF render run in the founder-gated release checklist, not every commit, because it needs a browser; keep the static print-CSS lint in `npm test`.
- Planted probes: a link to `/learn/nonexistent`; a `#missing-anchor`; a printable page with no `@media print`; a simplified page with no full-version link.
- Real fixture: every current Learn link.
- Extends: `test:slug-conventions`, `test:nginx-redirect-parity`, `test:entity-href`.

## Top 3
1. QA-R1 + QA-R2: put method facts in a data module that the existing `test:method-claims` imports, and prove the experiment equals `scoring.mjs` on a fixture table with band-edge and rounding cases. This closes DC-02's fifth occurrence before it happens.
2. QA-R4 + QA-R5: the privacy and duty-of-care scans on built output, with a recorded human sign-off per Explorer page. These protect children; both fail loudly and cheaply.
3. QA-R11: register Learn in the defect-class registry and the `npm test` chain first, with fail-on-zero-files, so the gates exist before the content does.

## What I would refuse to build
- Any experiment that has its own copy of the scoring maths ("simplified formula for kids"). Simplify the explanation, never the computation; if a simplified rubric is needed, label it "not the benchmark's score" and never render a band for it.
- Any text-entry box, "name your school" field, saved progress, score sharing, or leaderboard of children's results, even if local-only. The privacy gate would need exceptions, and exceptions are how trackers arrive.
- An "assess your school" tool that outputs a band name or a composite that resembles an official one. It would also invite the independence-firewall problem (learning appearing to raise or set a score).
- An automated "kid-safe" classifier or LLM moderation gate presented as sufficient. A vocabulary scan plus human sign-off is honest; an AI judge in CI is non-deterministic and cannot be a release gate in this repo's style.
- Waivers for Learn in `test:no-stale-counts` allowlists.
- Real-entity "worst performers" examples for any band under Analysts.

## Open questions for the founder (with defaults)
1. Umami on Learn: default page-view-only, no custom events, gated by an import ban; switch to fully off on `/learn/*` if any Explorer content is aimed at under-13s without a parent present.
2. Who signs off Explorer pages? Default: the founder, recorded in `docs/learn/review-log.json` with a content hash, and a gate that blocks a page whose hash changed since sign-off.
3. Reading-level ceilings: default FK grade 5 / 8 / 12 for Explorers / Investigators / Analysts as a ratchet baseline, to be recalibrated after the first pages are written and tried with real children or teachers.
4. Browser-based checks (PDF render, runtime network interception, real-contrast axe): default to a founder-run release checklist step, not part of `npm test`, to avoid adding a Chromium dependency to the pre-push chain.
5. Is the Investigators band allowed any real entity? Default: only from an explicit allowlist of institutions with benign framing (e.g. a university or a city library system), no country or conflict-affected entity below Analysts, and never in lowest-first order.
6. Educator packs and printables: default to generated at build time from the same data modules, carrying "as of <manifest date>", with no hand-typed PDFs in the repo.
7. Does the hand-rolled SVG chart library already meet WCAG title/desc conventions? Unverified here; default to auditing existing charts reused by Learn before reuse.
