# Agent Hub brief 12: QA (mechanical gating)

Lens: what must be gated by a test that fails closed, so the Agent Hub cannot publish what D-29a, D-52 and the duty-of-care rule forbid. All paths are relative to the repo root. Nothing here was run; it is a read of the existing gates and a design for their extensions.

## Findings about the current gates (verified by reading)

- The leak gates are well built: planted probes first, then the real tree, fail on zero, `--tree-only` for the build chain (`site/scripts/test-model-machine-leak.mjs`, `test-model-html-leak.mjs`, `test-model-report-seo.mjs`). But they derive "withheld values" from a committed wave file (`site/scripts/lib/model-report-html-gates.mjs`, `lib/model-machine-leak.mjs`). Hub content has no wave file. A gate keyed to withheld numbers will pass vacuously on Hub pages. Hub gates must be keyed to provenance class and field allowlists instead.
- `test:product-separation` (`site/scripts/test-product-separation.mjs`) guards entity-index fusion and uses fixtures only. It has no Hub concept; `meta.isModelIndex` discrimination is the closest hook.
- `tools/cb-probe/lib/outbound-guard.mjs` is the single choke point for local tool results: `official` never true, `comparability` exactly "none", no `rank`/`ranking`/`leaderboard` key anywhere, and any `composite`/`band` key must sit in a valid SelfRunScorecard. Remote MCP must reuse this module, not re-implement it.
- `sensitivity.mjs` excludes crisis items by default and `next_item` attaches the duty-of-care notice. I could not find "RPT-G7" in `site/scripts` (grep hit only `PANEL_BRIEF.md`). The ID is cited but its test is not locatable by name; Open question 1.
- DC-24 (`docs/DEFECT_CLASS_REGISTRY.md`) is exactly the Hub's central risk: a rule enforced on HTML but not on the JSON twin. DC-03 (narrating an unapplied proposal as an applied result) maps to a pending or self-run post narrated as a measured result. DC-18 (a detector that measures a proxy the target can trivially avoid) warns against regex-only "leak detection" on free text.

## Design principle for all gates

Gate on structure, not prose. Every Hub record carries a closed `provenance` enum (`measured_wave`, `self_run`, `self_assessment`). Renderers and exporters consume an allowlisted projection per class (like `projectWavePublic` in `lib/model-benchmark-public.mjs`). Gates assert (a) the projection allowlist, (b) every served byte of the built tree against forbidden patterns. Free-text scanning is the second layer only.

## Gate table

Timing key: B = before code (spec and fixtures first, test-first red), L = before launch, A = after launch (recurring).

### 1. Provenance-class leakage (B)
- Test: new `test:hub-provenance` in the `test:model-machine-leak` style. Walks every built Hub route, feed, JSON and `.md` twin. Every post/card node must carry `data-provenance` (HTML) or `provenance` (JSON) from the enum; a node with a missing or unknown class fails. A `self_run` or `self_assessment` node must be rendered with its label text ("self-run, not official" / "self-reported, unverified") and must contain no figure from the measured-wave namespace, no link to `/ai-models/reports/*` as supporting evidence, and no visual element shared with the measured card (same component, class or icon forbidden).
- Planted probe: a self-run post whose body reuses the measured card component; a self-run post with `provenance` stripped; a comment containing "Official result: 71.3"; a self-assessment card placed inside a "Results" container.
- Real fixture that must pass: a committed wave report card (measured), a recorded cb-probe SelfRunScorecard (self-run, as in `tools/cb-probe/tests/fixtures`), a D-52 self-assessment with 1-5 ratings.
- Extends: `test:model-report-seo` (lexicon and JSON-LD node checks) and `outbound-guard` rule 4 (composite only inside a validated scorecard). Add the class to the DC-03 registry entry as a recurrence guard.

### 2. Forbidden D-29a constructs (B for spec, L for tree)
- Test: extend `test:model-html-leak` and `test:model-report-seo` with a Hub pass: no rank/ordinal tokens next to a model name, no sort control, no DOM or JSON ordering that is a function of result (assert alphabetical order by name on every model list; add an order-invariance check: shuffle fixture scores, output order must not change), no bare score in `<title>`, meta, `og:*`, `twitter:*`, JSON-LD, feed XML/JSON, or OG image alt/filename; no band names beside a model; no `Dataset`, `ItemList`, `Rating`, `AggregateRating`, `Review` types; no per-model routes (`/ai-models/<model>`, `/agent-hub/models/*`). OG images: render from a template with no numeric input; test the generator signature accepts no score argument.
- Planted probe: a Hub index sorted by score; `<meta og:description="Pavo scores 71">`; a feed item titled "Top model this week"; an `ItemList` JSON-LD; a route per model; an agent profile page showing an ordinal "#3".
- Real fixture: current alphabetical report with "Not separated" grouping.
- "Relative standing": gate only the D-29a-compatible forms (interval-based separation statements derived by `lib/separation-statement.mjs`). Any rank-range or tier is forbidden until D-53 is ratified, so the gate stays closed by default.
- Extends: G19/G20 plus `test:mcp-pages` (it already uses mutate-and-must-fail assertions).

### 3. Evaluator-only fields and blinding keys (B)
- Test: `test:hub-json-allowlist`. Every served `.json` and the remote MCP responses are validated against a positive allowlist schema (deny by default), not a blocklist. Additionally scan keys and values for the set of internal field names, judge-to-subject maps, alias tables, run seeds, anchor corrections, hash salts, `judge`, `rater_model`, and the unblinded model identity of a blinded reply. Derive the forbidden set from `research/model-runs` harness schema field names at test time, never typed.
- Planted probe: the original DC-24 defect, a verbatim copy of an internal wave file under `public/data/`; a post JSON with a `blinding_key`; a reply object with the judge's model id.
- Real fixture: the projected public wave file.
- Extends: `test:model-machine-leak` (`publicWaveProblems`, `scanMachineTree`).

### 4. Crisis-item adjacency in the feed (B, then A)
- Test: `test:hub-crisis-adjacency`. Mark crisis items from the bank's sensitivity set (`tools/cb-probe/lib/sensitivity.mjs`, derived not typed). In the rendered feed and every paginated or filtered view: a post that references a crisis item must contain the care section; and within N DOM siblings (and N feed entries) there must be no CTA ("request a benchmark", Gumroad link) and no model figure. Check in the feed XML/JSON too, where order can place a crisis excerpt beside a figure.
- Planted probe: crisis excerpt without care section; crisis post followed immediately by a CTA card; a list view that truncates the care section; an OG description quoting the item text.
- Real fixture: a bank crisis item rendered with care section, isolated.
- Also gate that Hub search or tag pages cannot surface crisis text out of context.
- Extends: duty-of-care rule (RPT-G7 test, once located) and `sensitivity.mjs`.

### 5. Stored injection payloads (B)
- Test: `test:hub-escape`. Feed a corpus of payloads (script tags, `javascript:` URLs, attribute breakouts, markdown-to-HTML injection, SVG and `data:` URIs, RTL override, zero-width and control bytes, prompt-injection strings aimed at readers that are agents, JSON-LD `</script>` terminators) through the full pipeline: submit, moderate, build. Assert built HTML/JSON/XML contain only the escaped form: no raw `<script`, no event-handler attributes, no non-allowlisted scheme, valid XML, and JSON-LD has `<` escaped.
- Agent-readers: payload text must be wrapped as quoted, labelled data in `.md`/`llms*` twins, and instruction-shaped strings must not appear outside a clearly delimited untrusted block.
- Real fixture: a benign multilingual post with quotes, ampersands, emoji.
- Extends: `npm run test:no-control-bytes`; add a CSP check (no inline script) to the nginx config test.

### 6. Moderation visibility (B contract, L tree, A live)
- Test: state-machine test plus tree scan. Records have `status` in {pending, approved, rejected, withdrawn}. Build and API fixtures contain one of each with unique sentinel strings. Assert the sentinel of any non-approved record appears nowhere in `site/out`, feed, sitemap, search index, `llms*`, JSON, remote MCP responses, error messages, 404 bodies, or cached ETag listings. Assert withdrawal removes it from all of those on the next build, and that a count ("3 pending") never leaks.
- After launch: a scheduled live probe fetches the sentinels' known URLs from the deployed host and expects 404.
- Real fixture: one approved D-52 comment.
- Extends: `test:feed-freshness` (its tree scan machinery).

### 7. Remote MCP parity with local cb-probe (B for contract, L for run)
- Test: `test:mcp-remote-parity`. Run the same JSON-RPC conversation script (`tools/cb-probe/tests/e2e-jsonrpc.test.mjs`, `e2e-scored-run.test.mjs`) against local stdio and the remote handler. Assert identical tool names and input schemas, identical error codes, `include_sensitive` default false with the same duty-of-care notice, `official:false`, `comparability:"none"`, and that the remote path executes `outbound-guard.mjs` (import the same module; planted probe: a handler that bypasses it must fail). Remote-only extras: auth-less rate limits, request size caps, no session state shared across callers, artifacts never under a shared path (local `CB_ARTIFACT_ROOT` semantics must not become a shared writable root), and the no-network scan (`tests/no-network-scan.test.mjs`) stays true for the local package.
- Planted probe: remote `list_probe_items` returning crisis items by default; remote scorecard with `official:true`; a 13th remote-only tool that returns `rank`.
- Real fixture: the recorded local transcript.
- Extends: `outbound-guard.test.mjs`, `identification-required.test.mjs` (DC-18 occurrence 3 guard must hold remotely).

## Recommendations

- QA-R1. Add a closed provenance enum to every Hub record and make a missing or unknown value a build failure.
- QA-R2. Serve only allowlist projections per class; deny by default; DC-24 gate extended to the Hub tree.
- QA-R3. Route all remote MCP results through the existing `outbound-guard.mjs`; ship the parity test before the first remote endpoint.
- QA-R4. Extend G19, G20 and G24 with Hub passes; do not create parallel lexicons.
- QA-R5. Make every new gate mutate-and-must-fail (planted probe first), per `test:mcp-pages`.
- QA-R6. Moderation sentinels in the build fixtures; state-machine plus tree scan; post-launch live 404 probe.
- QA-R7. Crisis adjacency gate on feed order and every paginated or filtered view.
- QA-R8. An order-invariance test (shuffled scores yield identical output order) to catch implicit sort-by-result.
- QA-R9. Log each gate and its first red run in `docs/DEFECT_CLASS_REGISTRY.md` as the DC-03/DC-24 recurrence guard, and add all to the `npm test` chain and the pre-push chain.
- QA-R10. Add a recurring (A) job: weekly full-tree scan of the deployed site, not only the build output, diffed against the build.

## Top 3

1. Provenance enum plus per-class allowlist projection (QA-R1, R2): it prevents (b) and (c) from looking like (a) structurally.
2. Remote MCP must import the same outbound guard, with a parity test before any endpoint (QA-R3).
3. Moderation sentinel scan across every served surface (QA-R6): a pending post leaking is irreversible once cached or crawled.

## What I would refuse to build

- Any "sort by" control, leaderboard widget, or rank-range display before D-53 is ratified.
- Any feed where a model figure and a crisis item can be adjacent.
- Free-text-only (regex) moderation or leak detection with no structural gate.
- A remote MCP tool set that differs from the local one, or that writes to a shared artifact root.
- Rendering user content with raw HTML, markdown HTML passthrough, or inline scripts.
- Per-agent or per-model profile pages that accumulate results.
