# 07 — Data visualisation: relative standing, insight cards, self-ratings

Lens: the founder asked for "relative ranking" and "interesting insights". Every graphic below is hand-rolled static SVG
built on `site/src/components/model-benchmark/pilot/figure-kit.tsx`. That kit already provides a 480-unit viewBox,
`HWhisker`, `HAxis`, shape glyphs instead of colour, a caveat footer inside the SVG, and `<title>`/`<desc>` plus a
data table. All text is generated by predicates and checked by `assertLexicon` (`site/src/lib/model-report-facts.ts`).

## Grounding facts that shape the design
- The public wave file withholds points for every subject that is not separated, including dimension means and point
  differences (`site/public/data/model-waves/pilot-2026-10-03.json` `public_projection`, `derived.display_rule`,
  amendment 16). In pilot-2026-10-03 only `gemma2-9b-A` keeps a point. **A graphic or card that publishes per-item or
  per-dimension means for a withheld subject would let a reader reconstruct the withheld composite.** The `R-reconstruct`
  gate in `site/scripts/lib/model-report.mjs` exists for this reason.
- Bootstrap replicates are not committed, but they can be regenerated exactly: 1000 replicates, seed 20261003, item
  resampling paired across subjects (`method.interval`; `research/model-runs/bin/analyze-pilot.mjs` lines 199–231). Rank
  ranges therefore need one new analyzer output. Nothing has to be stored per replicate.
- A weekly wave has at most 3 subjects: the reference plus `max_new_subjects_per_wave: 2`. The reference runs at 1 trial
  (`research/model-runs/weekly/PROTOCOL.json`). With N=3, a rank range is nearly always "1 to 3 of 3" and tells the reader
  nothing. Relative standing across weeks can be honest only **against the reference**.
- G1 (intervals with "Not separated" brackets), G2 (paired differences, and a matrix only as a table above 15 pairs), G3
  (dimension ranges), G4 (length) and G5 (judges) already exist in `site/src/components/model-benchmark/pilot/PilotFigures.tsx`.

## Relative standing

**VIZ-R1 — Interval plot with separation groups. Reuse G1 unchanged.**
- **Question it answers:** where did each model land, and which models can the run not tell apart?
- **Complies with D-29a as written.**
- **Hub change:** embed the compact form, 480×(40 per model), in the run's feed post.

**VIZ-R2 — Pairwise distinguishability matrix, drawn as SVG.**
- **Question it answers:** for any two models, can this run tell them apart?
- **Encoding:** lower triangle only, alphabetical on both axes, with three glyphs:
  - filled square: separated after correction;
  - half square: separated only without correction ("stated in words, never as an ordering", amendment 16);
  - empty square: not separated.
- In a separated cell, a small chevron points to the row or column whose range is higher. Each cell's `<title>` carries
  the 95% interval (and the corrected interval where there is one). No point is printed.
- **Data:** `pairwise[]`, `comparisons[].bonferroni`, `derived.separated_pairs`.
- **Complies with D-29a**, because the order is alphabetical and every statement is a separation statement. Use it when a
  wave has more than 10 pairs; otherwise G2 is clearer.

**VIZ-R3 — Rank-range bars from the committed bootstrap. Needs D-53.**
- **Question it answers:** "Where could this model place, given the noise?"
- **Analyzer change:** `analyze-pilot.mjs` ranks the primary-arm subjects in every replicate, using the same seeded draw,
  and writes `derived.rank_range95[id] = [lo, hi]`, where position 1 is the highest pilot composite.
  `export-wave.mjs` hash-checks it like every other field.
- **Graphic:**
  - rows are alphabetical and grouped as in G1;
  - a horizontal bar runs across discrete slots 1…N, with the slots from lo to hi filled;
  - the label is "position 2 to 4 of 4, this wave only";
  - the composite range always sits beside it.
- **Shown only when the primary arm has N ≥ 4.** For weekly waves use VIZ-R4.
- **Risk:** for a cleanly separated model it reads "1 to 1 of 4", which is the closest thing here to a "#1". The
  amendment below prevents that from becoming a headline.

**VIZ-R4 — Reference-relative standing. Within one wave this complies with D-29a; the cross-wave view needs D-53 §5.**
- **Question it answers:** compared to the fixed yardstick, is this model above it, not distinguishable from it, or below it?
- **Encoding:** a diverging whisker of (subject − reference), with a zero line at the reference and the corrected
  interval dashed. This is exactly G2's grammar and uses the protocol-generated `comparisons`.
- Within one wave it is a paired-difference range, so it complies.
- **Cross-wave view (needs amendment):** every weekly subject's whisker from its own wave, stacked in alphabetical order.
  Rows from waves that failed the anchor check are hatched and labelled "not comparable".
- **Not covered:** comparisons between subjects from different weeks. Each whisker has its own judges and its own
  reference run. The caption must say so.

**VIZ-R5 — Reference-build stability series. Complies with D-29a: one build, no comparison.**
- **Question it answers:** is the instrument stable from week to week?
- **Encoding:** two aligned panels, with weeks on x.
  - Panel A shows the reference composite **range only**, one whisker per week. Its point is withheld because the
    reference is a one-trial variant (amendment 16).
  - Panel B shows the anchor mean absolute difference as a dot, with a dashed threshold line at
    `anchor.max_mean_abs_difference` (0.30) read from the protocol, never typed in.
- **Rules:**
  - **Never connect the dots and never fit a trend.** Fewer than 4 waves renders as a table.
  - The reference point from pilot-2026-10-03 (3 trials) is excluded from the series and footnoted, because it is not
    like-for-like.
- **Annotation predicate:** "All N weekly anchor checks were under the threshold", or "Week W exceeded the threshold;
  that wave is marked not comparable."

### Draft amendment D-53 (minimal; amends D-29a §3 only; D-29a otherwise stands)
> **D-53 — Rank ranges and reference-relative standing in unofficial reports.**
> 1. For a wave whose primary arm has at least four subjects, a report may show each primary-arm subject's 95% rank range: the 2.5th and 97.5th percentiles of its position across the wave's seeded bootstrap replicates, written by the analyzer to the committed, hash-checked wave file. Position 1 is the highest pilot composite.
> 2. It is always written "position *a* to *b* of *N*, this wave only", including when *a* = *b*. It is never written as a single ordinal, "#", "top", "first" or "leading", and never shown with a medal, crown or colour.
> 3. Rows stay alphabetical, in "Not separated" groups. A rank range is never a sort key, a default order or a sort control. It is never shown without the composite range beside it.
> 4. Rank ranges are never shown for one-trial or secondary-arm subjects, never combined or compared across waves, and never placed in a headline, title, meta, JSON-LD, feed card heading or OG image.
> 5. A report may list subjects from different weekly waves together only as each subject's corrected paired difference against the reference build in its own wave, alphabetically, with waves that failed the anchor check marked "not comparable". It may not state an order between subjects from different waves.

## Insight cards (the feed)

**VIZ-R6 — A single card grammar.** Each card has:
- a **kind**;
- a **claim sentence** generated by a predicate, where a false predicate fails the build (the G1–G5 pattern);
- a **figure-let** of at most 480×140, with the status line and run id drawn inside the SVG;
- a "**What this does not mean**" line;
- a **source block**: wave path, `source_sha256`, and the JSON pointers of every number shown.

A test re-derives each displayed number from its pointers. Feed cards show **ranges only**, never a point, because D-29a §3
bars bare points in feeds. Card ids are content hashes, never model names, because D-29a §1 forbids per-model anchors.
The card kinds:

| Kind | Fires when | Wave source | Exists today? |
|---|---|---|---|
| SEPARATION | a corrected separated pair exists | `derived.separated_pairs`, `comparisons[].bonferroni` | yes |
| DIMENSION GAP | two dimension ranges within one model do not overlap, **and** a Bonferroni within-model paired check agrees | `dimension_intervals95` + new `within_subject_dimension_pairwise` | partial |
| JUDGE DISAGREEMENT | `responses_differing_by_2_or_more` > 0, or every judge's leniency for a subject has the same sign | `subjects.*.judge_agreement`, `judges.*.by_subject` | yes |
| LENGTH CONFOUND | `length_check.per_build[].length_instruction == "ineffective"`, or a separated model is in `composite_if_pooled_slope_removed` | `length_check`, `length` | yes |
| DRIFT | anchor MAD > `PROTOCOL.anchor.max_mean_abs_difference`, or the corrected reference-vs-previous-week interval excludes 0 | `bridge_drift` now; new `anchor_check`, `reference_vs_previous` | partial |
| FLOOR ITEM | every subject's item mean is ≤ 1.5 on a served item | new `derived.floor_items: [{item_id, dimension}]` | no |
| REPLICATION | `replication.separation_repeats` is defined | `replication` | yes |

Rules for the kinds:
- **DIMENSION GAP:** if the same gap appears in every model, the card becomes an *instrument* card ("a finding about the
  test", the G3 rule) and names no model. It shows ranges only.
- **FLOOR ITEM:** publish only the item id, its dimension and the boolean, never per-subject item means
  (reconstruction). Sensitive items are never served (`crisis_items_served: false`), and the card asserts this. It names
  no model.

**VIZ-R7 — Card provenance must be visible in the graphics.** Only a type (a) card, a benchmark we ran blinded and
cross-judged, may carry a figure-let. A type (b) self-run card has no SVG and no number in the feed; its first word is
"Self-run", it has a dashed frame, and it links to its artifact. A type (c) self-assessment card has no SVG and no
number. Because a self-run card can never contain a chart, it can never look like a type (a) card, and this does not
depend on colour.

## Self-ratings (D-52)

**VIZ-R8 — Self-ratings are shown as text only, in words, inside the entry, and are never drawn.**
- They use the same 1–5 scale as G3's axis, so any graphic invites the reader to place a self-rating against a measured range.
- **Form:** "Empathy: self-rated three of five (self-reported, unverified)", in the fixed dimension order. This is a
  one-word change to ASA-DSP-03 AC2 in `docs/PRD_AGENT_SELF_ASSESSMENT.md`, from "n" to "n in words".
- **Never shown:**
  - in feed cards, the thread index, OG images or JSON-LD;
  - on any `/ai-models/reports` page.
- **No join between the two surfaces:** no link from a report figure to a model's self-assessment thread, and thread
  slugs must not reuse wave subject ids.

## Scoring (Impact + Alignment + Learning + Confidence − Effort − Risk, each scored 1–5)
- **R6 cards (SEPARATION, LENGTH, JUDGE, REPLICATION):** 5+5+4+5−2−1 = 16.
- **R5 stability series:** 4+5+5+4−2−1 = 15.
- **R4 within one wave:** 4+5+3+5−1−1 = 15.
- **R2 matrix:** 3+4+3+5−2−1 = 12.
- **R3 rank ranges:** 5+5+3+3−3−4 = 9, because they are gated on D-53.

## Top 3 recommendations
1. **VIZ-R6/R7: the insight card grammar, with ranges only and figures only for runs we ran.** Readers finally see
   *what is interesting* in a run, with every number traceable to a hash-checked pointer.
2. **VIZ-R4/R5: reference-relative whiskers and the stability series.** Readers learn how a new model stands against a
   fixed yardstick, and whether the yardstick itself held that week.
3. **VIZ-R3 under D-53: rank ranges, for waves of 4 or more only.** Readers get the honest answer to "where does it
   rank": a range of positions, never a single position.

## What I would refuse to build
- A cross-wave leaderboard, or any single list ordered by result.
- A radar or spider chart of self-ratings, or self-ratings on a 1–5 axis.
- Per-item or per-dimension means for withheld subjects in any card.
- Connected lines or fitted trends over fewer than 4 waves.
- An OG image per card.
- A "1 of N" badge.
