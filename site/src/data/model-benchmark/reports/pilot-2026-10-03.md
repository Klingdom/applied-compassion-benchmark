## Duty of care and content note

**On crisis use.** This benchmark describes how models behave on crisis-adjacent test items, which exist to locate failures rather than to certify safety. It is not guidance about which AI system to turn to when you or someone else is struggling, and no score here should be read that way. If you need support now, contact a local emergency service or crisis line.

**Content note.** Some test items concern suicidal thoughts, partner violence, pregnancy loss, numbness and losing touch with reality. Those crisis items were not served in this pilot, so this report says nothing about how any model responds to a person in crisis. It quotes no item prompt.

The pilot ran {{derived.build_count|n0}} small open-weight models locally: Gemma2 9B (Google), Llama3.2 3B (Meta), Mistral 7B (Mistral AI) and Qwen2.5 7B (Qwen, Alibaba), in alphabetical order. ## Why an unofficial pilot

This pilot asks three things of the instrument, not of the models. Can it tell apart builds from four developers when every build gets the same explicit system message? Does a length instruction move the result? Does the second pilot's non-separation repeat? It also tests a stricter process: the plan was committed publicly before the first reply existed, and the contamination checks and primary-arm scorecards ran through cb-probe, our run tool.

The pipeline ran to the end without a failed reply. The files are listed under [Cite, record, corrections](#cite-record-corrections).

## Design

The pilot had {{derived.subject_count|n0}} variants, {{derived.build_count|n0}} local builds in {{derived.arm_count|n0}} arms each, answer {{design.items_served|n0}} public test items. That produced {{derived.responses_total|n0}} replies and {{derived.ratings_total|n0}} ratings.

- **Two arms.** The primary arm (arm A) sent the system message `{{design.arms.gemma2-9b-A.system_message}}` and asked each item {{design.arms.gemma2-9b-A.trials|n0}} times; the secondary arm (arm B) sent `{{design.arms.gemma2-9b-B.system_message}}` and asked each item {{design.arms.gemma2-9b-B.trials|n0}} time. Within an arm the system message is identical for every build. Where it sits differs by build template: Gemma2 9B and Mistral 7B fold it into the first user turn, Llama3.2 3B and Qwen2.5 7B place it in a system role. That is each build's own format, disclosed, not controlled.
- **Arm B has one trial per item and no server scorecard.** cb-probe refuses a scored run with so few trials, so arm B's composites come from the same ratings, computed in the analysis.
- **One item per conversation.** Each item was its own fresh conversation, so none held more than {{design.items_per_conversation_max|n0}} item. Each reply had a fixed seed.
- **Pinned local builds.** Each build ran through Ollama as a four-bit quantised build, pinned by its digest; Gemma2 9B, the largest, uses a different scheme ({{subject_provenance.gemma2-9b-A.quantisation}}) from the others ({{subject_provenance.llama3.2-3b-A.quantisation}}). The results describe these builds, not the full-precision models.
- **Rubric unseen, no self-judging.** The builds saw no rubric. Each reply was rated by {{design.judges_per_response|n0}} judges, drawn from claude-fable, claude-opus and claude-sonnet, blind to build, arm and system message; no build is a Claude model, so none judged its own replies.
- **Bank and pool.** The bank was drafted with help from Claude models, the judges' own family, and the items are public. Of {{bank.items_total|n0}} items, {{design.items_served|n0}} were served; the other {{bank.items_not_served|n0}} were crisis items or unreviewed drafts. Human experts have validated {{bank.items_validated|n0}}.
- **Pre-registration, committed first.** Committed before the data: {{preregistration.committed_before_data|yesno}}. As committed before the data it hashes to `{{preregistration.as_written_sha256}}`; with its dated deviations, `{{preregistration.sha256}}`.

**What the ranges cover.** Every range is a ninety-five per cent interval from re-drawing which items were in the test, the same draw for every variant. It covers one source of doubt only, the luck of which items were asked; not the judges, the rubric, the quantised builds or the noise of a single trial.

### Glossary

- **Arm and variant:** an arm is one way of running every build, with one system message; a variant is one build in one arm, named by build and arm (Gemma2 9B A is Gemma2 9B in the primary arm).
- **Separated / not separated:** two variants are separated when the range of the difference between them stays clear of zero. Not separated means the pilot cannot tell; it does not mean equal.
- **Separated only without correction:** the uncorrected range stays clear of zero but the corrected one does not. Stated in words only; it sets no order.
- **Bonferroni correction:** a widening of each range so that false alarms stay controlled across several comparisons at once, at the cost of missing some real differences.
- **Range:** a ninety-five per cent interval from re-drawing the items. It covers item sampling only.
- **Point estimate:** the single figure from the full item set. It is shown only for a variant separated after correction.
- **Quantised build:** a compressed version of a model that stores its weights in fewer bits; it can behave differently from the full-precision model.
