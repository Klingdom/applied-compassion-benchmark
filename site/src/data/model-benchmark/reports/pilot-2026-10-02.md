## Duty of care and content note

**On crisis use.** This benchmark describes how models behave on crisis-adjacent test items, which exist to locate failures rather than to certify safety. It is not guidance about which AI system to turn to when you or someone else is struggling, and no score here should be read that way. If you need support now, contact a local emergency service or crisis line.

**Content note.** Some test items concern suicidal thoughts, partner violence, pregnancy loss, numbness and losing touch with reality. Those crisis items were not served in this pilot, so this report says nothing about how any model responds to a person in crisis. It quotes no item prompt.

## Why an unofficial pilot

The first pilot tested Claude models with Claude judges. This one asks whether the same pipeline can test models from other developers, judged by models outside the subjects' family, with each item in its own fresh conversation, a judge-validity rule fixed before any rating existed, and the scoring and contamination checks run through cb-probe, our run tool, end to end, using the cb-probe server in the repository's working tree at the time, before the corresponding changes were committed.

The pipeline ran to the end without a failed reply; the test could not separate the two models. The main files are listed under [Cite, record, corrections](#cite-record-corrections), so anyone with the repository can check the figures.

## Design

The pilot had {{derived.subject_count|n0}} local models answer {{design.items_served|n0}} public test items {{design.trials_per_subject|n0}} times each. That produced {{derived.responses_total|n0}} replies and {{derived.ratings_total|n0}} ratings.

- **One item per conversation.** Each item was sent as its own fresh conversation, one user turn from us holding the prompt text only, so no conversation held more than {{design.items_per_conversation_max|n0}} item. Each reply had its own fixed seed, so replies are set up to be reproducible; we did not rerun any to test it.
- **Pinned local builds.** Llama3.2 3B is Meta's {{subject_provenance.llama3.2-3b.parameter_size}} model and Qwen2.5 7B is Qwen's {{subject_provenance.qwen2.5-7b.parameter_size}} model. Both ran as {{subject_provenance.llama3.2-3b.quantisation}} four-bit quantised builds through Ollama {{subject_provenance.llama3.2-3b.runtime_version}}, each pinned by its digest, so a rerun can check it is using exactly these builds. The results describe these builds, not the full-precision models.
- **The rubric was unseen.** We sent only the messages: no item labels, dimensions or marking guide, and no system prompt of our own. A leak check screened every outgoing message. The builds add default text of their own, which we did not change: the Qwen2.5 7B build carries a built-in system line that names it as Qwen, made by Alibaba Cloud, and the Llama3.2 3B template adds a header of its own.
- **No self-judging.** Each reply was rated by {{design.judges_per_response|n0}} judges, drawn from claude-fable, claude-opus and claude-sonnet, and never told which model wrote it. No subject is a Claude model, so no model rated its own replies.
- **Bank drafted with Claude help.** The item bank was drafted with help from Claude models, the judges' own family.
- **Public pool.** The items are published. A model could have met them in training.
- **Items left out.** {{bank.items_total|n0}} items are in the bank and {{design.items_served|n0}} were served. The other {{bank.items_not_served|n0}} were not: {{bank.items_not_served_sensitive|n0}} contain crisis content and {{bank.items_not_served_unreviewed|n0}} are unreviewed drafts.
- **Unvalidated items.** Human experts have validated {{bank.items_validated|n0}} of the bank's {{bank.items_total|n0}} items.
- **Pre-registration.** The plan was written before any reply to a test item existed. It was not committed or time-stamped before the data existed (committed before the data: {{preregistration.committed_before_data|yesno}}), so nothing outside this project proves when it was written. As written it hashes to `{{preregistration.as_written_sha256}}`; with its three dated deviations appended, to `{{preregistration.sha256}}`. The deviations sit below the plan text, which is unchanged, so removing them reproduces the first hash, as the repository test `research/model-runs/tests/preregistration-integrity.test.mjs` checks.

**What the ranges cover.** Every range is a ninety-five per cent interval from re-drawing which items were in the test, many times over, with each dimension's share fixed and the same draw for both models. It covers one source of doubt only: the luck of which items were asked. It does not cover the choice of judges, their shared family, the rubric, who drafted the items, the quantised builds, or run-to-run variation, so the real uncertainty is larger than the ranges show.

## Separation

**The two models could not be told apart.** On 2026-10-02, Compassion Benchmark's unofficial pilot (`pilot-2026-10-02`; not a score) could not tell Llama3.2 3B and Qwen2.5 7B apart (alphabetical order; local four-bit builds). The range of the difference between them includes zero. The pilot cannot say which is higher; that is not the same as equal.

The basic unit is the pair: on the same item draws, does the range of the difference stay clear of zero? Here it does not. This was the pre-registered question, and on the pre-registered criterion the instrument did not separate these two builds on this bank.

## Separated model and reply length

No model was separated, so there is no separated model to report. The reply-length question still applies to both models, and its answer is unresolved.

Start with the word counts. Llama3.2 3B's median reply was {{subjects.llama3.2-3b.median_reply_words|n0}} words and Qwen2.5 7B's was {{subjects.qwen2.5-7b.median_reply_words|n0}} words. Medians hide the short end: the two models differed in how many very short replies they gave, so they differ more in length than these medians show.

Next, the slopes. On the same item, across both models, longer replies were rated somewhat higher: the correlation between reply length (on a log scale) and rating was {{length.pooled_within_item_r|n2}}, and the pooled slope was {{length.pooled_within_item_slope|n2}}. Within each model's own replies the slopes were {{length.within_subject_slopes.llama3.2-3b|n2}} (Llama3.2 3B) and {{length.within_subject_slopes.qwen2.5-7b|n2}} (Qwen2.5 7B). No range was computed for any slope, so neither slope is a finding on its own, and the pooled slope also carries whatever differs between the models.

Judges rated each reply on its own, never two side by side, so this pattern is across replies, not a measured preference for the longer reply. Judges were told that length is not a criterion; that instruction cannot prove the bias is absent. Whether length moved either model's ratings, and by how much, is unresolved.

## Deviations and what went wrong

Each item is tagged pre-registered (fixed before any reply existed) or post-hoc (appended to the plan, dated, after replies existed).

- **Pre-registered: the judge-validity rule.** Before any figure was computed, each judge's share of evidence quotes not found in the reply was measured against a {{judge_validity.measured_on_original_answers.threshold_percent|n0}} per cent threshold. On the original answers, before any requote, quotes not found were {{judge_validity.measured_on_original_answers.judges.claude-fable.unfound|n0}} (claude-fable), {{judge_validity.measured_on_original_answers.judges.claude-opus.unfound|n0}} (claude-opus) and {{judge_validity.measured_on_original_answers.judges.claude-sonnet.unfound|n0}} (claude-sonnet), out of {{judge_validity.measured_on_original_answers.judges.claude-sonnet.ratings|n0}} each. On the final quotes, the basis the plan names, the count was {{judge_validity.measured_on_final_quotes.judges.claude-sonnet.unfound|n0}} for every judge. All three passed on both readings, and no judge was excluded.
- **Post-hoc, {{deviations.0.id}}: the short-quote rule clarified.** Recorded after the replies existed, and by our record before any rating (the plan file does not time-stamp individual entries): a quote is re-asked if it is under twelve characters or under three words, the rule cb-probe itself enforces. It only widened the requote set.
- **Post-hoc, {{deviations.1.id}}: how the run sits inside cb-probe.** Recorded, by our record, before any rating. cb-probe stores one rating per item and trial, so each reply's two ratings were entered as separate trials. Its scorecard's own interval therefore describes trial noise only; the ranges in this report read the replies and ratings directly and are unaffected.
- **Post-hoc, {{deviations.2.id}}: two operational steps during judging.** Before any rating, {{operations.judge_batches_planned_as_two_halves_before_any_rating|n0}} of {{operations.judge_batches|n0}} judge batches were sent as two halves to fit a judge's reading limit. During judging, batch {{operations.judge_batches_redelivered_as_two_halves_after_incomplete_answers.0}} (claude-fable) twice came back missing the same entry, a one-sentence refusal; its {{operations.judge_calls_voided|n0}} incomplete files were voided and kept (in the run's `judge-answers-voided` folder), and the batch was re-sent as halves. No rating was edited or imputed.

**What went wrong, and what we disclose.**

- **The pre-registration's timing.** It was not committed until after the data existed, so its timing rests on our word (see Design).
- **The blind has gaps.** {{self_identifying_replies.by_subject.llama3.2-3b|n0}} replies from Llama3.2 3B and {{self_identifying_replies.by_subject.qwen2.5-7b|n0}} from Qwen2.5 7B named the model or its developer, so a judge could infer the source of those. They were scored like every other reply. Qwen2.5 7B's built-in system line names its developer, which may account for them.
- **Post-hoc: replies echoing rubric phrases.** {{operations.subject_replies.llama3.2-3b.replies_flagged_by_reply_side_phrase_check|n0}} replies from Llama3.2 3B and {{operations.subject_replies.qwen2.5-7b.replies_flagged_by_reply_side_phrase_check|n0}} from Qwen2.5 7B shared short, common phrases with the rubric's anchor text, such as "it's completely normal to feel"; one Llama3.2 3B hit was a dimension code inside an unrelated spreadsheet answer. They were kept verbatim, not dropped. The plan said to run this check on saved replies but set a stopping rule only for outgoing messages, so keeping them was a post-hoc choice; no outgoing message was flagged.

## Why these are not scores

These limits are listed in no measured order of risk.

- **Judges from one family.** Every judge was a Claude model, from a different model family than the models tested. That removes self-judging, but a family-wide leniency or severity toward other developers' writing cannot be ruled out, and the item bank was drafted with Claude's help as well.
- **Quantised local builds.** The results describe these pinned, four-bit quantised local builds, not the full-precision models or any hosted version.
- **No human raters.** No person rated any reply, so nothing in this pilot checks the judges' marks against human judgement.
- **Unvalidated items.** {{bank.items_validated|n0}} of {{bank.items_total|n0}} have passed human review; some may not test what they claim.
- **Public pool.** The items are published, so a model may have met them in training. Our probes sampled only a few.
- **Two models, one run.** One build of each, one runtime, one sampling setup and one day of judging.
- **Reply length.** Longer replies were rated somewhat higher across the pilot, and the cause is unresolved.

This pilot is not a score and cannot be compared with the AI Labs Index, any other index on this site, or the first pilot: the answering protocol differs (one item per conversation here, many in the first pilot), the judging sessions differ, and the bridge sample above is descriptive only.

### Glossary

- **Separated / not separated:** two models are separated when the range of the difference between them stays clear of zero. Not separated means the pilot cannot tell; it does not mean equal.
- **Range:** a ninety-five per cent interval from re-drawing the items. It covers item sampling only.
- **Point estimate:** the single figure from the full item set. It is not shown for a model in a not-separated group.
- **Quantised build:** a compressed version of a model that stores its weights in fewer bits; it can behave differently from the full-precision model.
- **[Empathy](/dimensions/empathy) (EMP):** one of the eight dimensions the test rates.
